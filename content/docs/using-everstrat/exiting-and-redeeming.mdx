## Review and submit

1. Select **Burn**, enter an EVE amount, and review the estimated ETH and max slippage.
2. If the app shows **Approve EVE**, verify the AMM spender and allowance, confirm the approval
   transaction, and wait for its receipt. Approval does not submit an exit.
3. Review the quote again, then select **Burn** and confirm the separate exit transaction.

The maximum EVE input caps both immediate burning and queued escrow; price tolerance
additionally checks queued settlement against the request-time price. Read
[Pricing & the bonding curve](/how-everstrat-works/pricing-and-bonding-curve#transaction-protections)
for the exact protection on each path. Keep ETH in your wallet for gas.

## Current queued flow and conditional immediate exits

At the [dated snapshot](/operations/current-deployments#exit-liquidity-at-this-block), AMM free ETH
is zero and routine float top-up is disabled. New successful exits therefore queue; deposits
forwarded to Controller do not replenish AMM free ETH.

Code supports immediate burning and ETH payment in one transaction only if sufficient free
AMM ETH becomes available. That branch needs no separate Claim, but is not funded at the snapshot.

On the queued path, EVE is escrowed on the AMM and the request waits in ExitQueue.
Keepers must price and process it. Submission, processing, and withdrawal are separate events:

| State | What it means for you |
| --- | --- |
| Queued and unprocessed | EVE is held by the AMM; ETH has not been paid. Review the request on Portfolio. |
| Processed successfully | EVE is burned and ETH is credited, but still held for your Claim. |
| Claimed | A separate Claim transaction transfers credited ETH to your wallet. |
| Closed for slippage | EVE is returned instead of ETH; review a fresh quote before trying again. |
| Cancelled | Escrowed EVE is returned; this is not an ETH redemption. |

## Claim credited ETH

When ETH is available to claim, select **Claim** on **Portfolio**, confirm in your wallet,
and wait for confirmation. A successful Claim withdraws the available credited balance, which
can include more than one processed request. It is not necessarily a one-request payout.

Processed requests cannot be cancelled. Their credited ETH remains claimable after the
queue processing window ends. AMM pause alone does not block Claim or eligible cancellation.

## Pending requests and cancellation

An existing pending request in the current batch can block another exit submission.
Review the request on Portfolio instead of repeatedly clicking Burn.

Cancellation is available before batch pricing, or after the processing window expires
for a request that is still unprocessed. During the priced processing window, cancellation
is blocked. Strictly more than three days after pricing, an unprocessed request cannot
be settled at all: cancel it to recover EVE. Waiting longer will not make that request
payable. A later redemption requires a new request and quote. Already credited ETH remains
claimable. Cancellation returns EVE, not ETH.

For the exact minimum size, batch timing, tolerance checks, and cancellation boundary,
see [The redemption queue, in depth](/how-everstrat-works/redemption-queue).
The queue keeper's scheduling policy is described in
[Keepers and automation](/contracts/keepers-and-automation).

## Common blockers

- **Minimum queued amount:** use the live warning and ETH quote, not a fixed remembered EVE
  threshold. The minimum is ETH-denominated, so its EVE equivalent changes with price.
- **AMM paused or NAV unavailable:** normal exit submission may be blocked. Check current
  state; do not assume a previously displayed quote is still usable.
- **Keeper delay or insufficient liquidity:** there is no guaranteed completion time.
  Check request state and eligible actions rather than assuming a pending exit has failed.
- **Approval pending:** wait for confirmation before submitting Burn. If the amount changes,
  the app may require a different allowance.
