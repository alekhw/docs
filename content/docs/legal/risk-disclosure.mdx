listed in order of importance.

The detailed technical account lives in [Key risks](/risk-and-trust/key-risks),
[Security and audits](/risk-and-trust/security-and-audits) and

disclosure rather than a summary of it. Read them before you transact.

## Testing phase — treat as a test protocol

Everstrat is in a **testing phase**. The contracts run on Ethereum mainnet, so the ETH you deposit
is real and so are any losses. Being on mainnet does not make this a production system: the
protocol should be treated as a **test protocol** — experimental, invite-gated, unaudited, and
subject to change or suspension without notice.

Because real funds are now involved, **verifying you are on the official deployment matters.**
Only interact with the addresses listed in [Contract addresses](/reference/contract-addresses).
Anyone asking you to send funds to a different "Everstrat" contract, site or token is defrauding
you. There is no sale, no presale and no allocation. Treat any message, site, token or account
claiming otherwise as an impersonation attempt, including ones that copy this documentation.

## The code is not audited

No third party has audited the smart contracts. There is no completed audit report, no bug bounty
and no formal verification.

Verified source code on a block explorer means the published source matches the deployed bytecode.
It does not mean the code is correct, and it is not a substitute for an audit.

The current position on audits, and what would have to happen before one, is described in
[Security and audits](/risk-and-trust/security-and-audits).

## Your deposit is exposed to strategy performance

EVE tracks the net asset value of a portfolio. If the strategies lose value, every EVE is worth less
ETH. There is no principal protection, no floor price and no guarantee of recovery.

Essentially all pooled capital currently flows into a single strategy contract, UniCLStrat, which
provides concentrated liquidity on Uniswap V3. Capital is spread across several pools, but every pool
runs the same contract code, so a flaw in that contract could affect all capital deployed to
strategies, and the spread across pools offers only limited diversification. Concentrated liquidity
positions can also underperform simply holding the underlying assets. See [Key risks](/risk-and-trust/key-risks).

## Exiting is not guaranteed to be immediate

If the AMM lacks free ETH to fill your exit, the request is queued and waits for a keeper to process
it. If the keeper is offline, your ETH is not accessible in the meantime.

An escape hatch exists: you can recover your EVE tokens, though not ETH, under the conditions
described in [Key risks](/risk-and-trust/key-risks). Recovering EVE leaves you holding EVE, and you
would need to attempt a new exit.

## Privileged roles exist

Everstrat is not a system with no operators. Management contracts are upgradeable behind a timelock,
an emergency pause can halt activity, and a keeper processes queued exits.

These powers are real and they are held by people. What each role can and cannot do is set out in
[Trust and governance](/risk-and-trust/trust-and-governance). Anyone describing this protocol as
fully autonomous or fully decentralised is overstating it.

## Transactions are irreversible and public

Transactions you sign are written to the blockchain, and no one can reverse or delete them. Nobody
can recover a private key, undo a mistaken transaction, or restore access to a lost wallet.

Wallet addresses and transaction histories are public and permanent. This applies on mainnet as it
does anywhere else.

## The software depends on services nobody here controls

The interface relies on RPC providers, a subgraph indexer, wallet software, an oracle and the
Ethereum network itself. Any of them can be slow, wrong, unavailable or compromised, and the
interface can display stale or incorrect figures as a result.

On-chain state is authoritative. What an interface shows is not.
