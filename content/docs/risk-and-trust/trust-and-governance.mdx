## What you are trusting

You rely on contract correctness, governance decisions, accurate NAV reporting, and
available strategy and queue automation. The timelock provides advance visibility,
not principal protection or a guaranteed opportunity to exit before an upgrade.

## Role model

| Role | Authority | Holder at the dated snapshot |
| --- | --- | --- |
| ADMIN | Parameters, peer registration, role management, strategy registration/removal, single-strategy Controller withdrawal, oracle configuration, unpausing, and UUPS upgrades | Timelock |
| SECURITY | Designated pause/emergency paths, supported ERC-20 accounting removal, and Whitelist signer revocation | Security Safe |
| KEEPER | Controller strategy operations and queue pricing/processing | The two keeper executor contracts |
| MINTER | EVE mint and burn functions | AMM and StrategyManager |
| CONVERTER_CALLER | Approved strategy conversions | Registered strategies |
| CONVERTER_CALLER_MANAGER | Management of converter caller grants | Converter |

Registered peer checks, such as AMM accepting processing only from Controller, are separate
from Registry role grants. Oracle configuration requires ADMIN, not a separate oracle-manager role.

See [Roles and permissions](/security/roles-and-permissions) and the
[dated role/address snapshot](/operations/current-deployments#role-holders).

## The 48-hour timelock

At the snapshot, ADMIN is held by the timelock and `getMinDelay()` is **48 hours**.
A scheduled operation must mature and then be executed. "Ready" does not mean "Done";
a merged proposal or signed Safe transaction does not prove execution.

The Security Safe can cancel timelock operations under its CANCELLER permission.
Immediate SECURITY paths do not wait for the ADMIN delay.

The review window is **not an exit guarantee**. An exit can be paused, depend on NAV
availability, or need a queue that takes longer than the timelock delay. Cancellation
returns EVE, not ETH.

## SECURITY limits and accounting effects

SECURITY cannot unpause or authorize UUPS upgrades. It can pause designated modules,
use their authorized emergency recovery paths, and remove a supported ERC-20 from
StrategyManager. That removal is a configuration exception: it drops that token's value
from NAV accounting without recovering its assets. It must not be described as
configuration-free emergency authority. `Whitelist.removeSigner()` is another configuration
exception: SECURITY can revoke a signer while the Whitelist is enabled, but cannot add a
signer or disable the Whitelist.

Pausing is per contract, not a global Registry switch. Strategy emergency recovery requires
the strategy to be paused and permits ADMIN or SECURITY.

Cancellation of an eligible queued request and withdrawal of already claimable ETH
remain available through AMM during pauses.

## Immutable versus upgradeable

| Component | Code model |
| --- | --- |
| Registry, EVE, AMM, Whitelist, keeper executors | Static deployed code, with configurable permissions or settings |
| Each UniCL strategy | Immutable instance; replacement uses new deployment and registration |
| Controller, StrategyManager, ExitQueue, Oracle, Converter | ADMIN-authorized UUPS upgrades |

Immutable AMM code still depends on configurable peers and upgradeable NAV/queue contracts.
Immutable strategy code still depends on feeds, routes, and external pools.
Fixed bytecode does not make economic behavior independent of governance.
