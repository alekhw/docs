---
title: Immutable vs upgradeable components
description: Which contracts are intentionally static and which use UUPS proxies.
---

## Immutable Core

- `EVE`
- `AMM`
- `Registry`, `Whitelist`, and the keeper executors
- each deployed UniCL strategy instance

These contracts are treated as the “code is law” core.

## Upgradeable Management Layer

- `Controller`
- `ExitQueue`
- `StrategyManager`
- `Oracle`
- `Converter`

These contracts use UUPS and therefore depend on `ADMIN_ROLE` for upgrade authorization.

Fixed bytecode does not mean fixed configuration. Registry peers, roles, feeds, routes,
and parameters can still change. A new immutable strategy must be deployed and registered,
not upgraded in place. See [Current deployments](/operations/current-deployments).

## Design Tradeoff

The repository splits the system between:

- fixed user-facing entry/exit mechanics
- adaptable management and operational contracts

That reduces upgrade surface on core mint/burn logic while preserving room to evolve queue and
strategy operations.
