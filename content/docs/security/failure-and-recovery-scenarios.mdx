## Common Scenarios

<Accordions type="single">
  <Accordion title="Queue processing is delayed">
    An unprocessed request can be cancelled strictly more than three days after pricing, returning
    EVE rather than ETH. Unpriced requests can be cancelled without that wait.
    Processed requests instead require a claim. The app checks eligibility from RPC state.
  </Accordion>
  <Accordion title="Queued redemption moves outside tolerance">
    The request can close due to slippage instead of redeeming ETH. In that case the user receives
    token refund semantics rather than settlement.
  </Accordion>
  <Accordion title="Subgraph is behind the chain">
    Historical activity may lag. Balances, claimable ETH, current-batch state, and indexed pending
    requests are checked through RPC independently of activity pagination.
  </Accordion>
</Accordions>

## Operational Recovery

- pause designated modules when necessary, including static contracts with pause controls
- process or close queued requests according to protocol rules
- re-run or redeploy subgraph versions when indexing assumptions change
