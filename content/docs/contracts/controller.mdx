title: Controller
description: Upgradeable coordinator for strategy funding, queue pricing, and redemption processing.
---

Controller receives ETH from AMM and coordinates StrategyManager and ExitQueue.
It is a UUPS proxy, with upgrades authorized by ADMIN through the timelock.

## Operational functions

KEEPER coordinates strategy deposits, withdrawals, rebalances, synchronization,
batch pricing, request processing, and AMM exit liquidity.
Performance-fee harvest functions allow ADMIN or KEEPER.
ADMIN or SECURITY can pause and perform the designated emergency transfer to AMM;
unpausing requires ADMIN.

Downstream contracts authenticate Controller through the Registry's registered
`CONTROLLER` address. There is no separate `CONTROLLER_ROLE`.

## Deployed version versus proposed upgrade

At the [October 11 snapshot](/operations/current-deployments), Controller reports **1.0.0**.
Its `withdrawFromStrategy(address,uint256)` function is KEEPER-only.

Contracts main contains **1.1.0**, which adds ADMIN access to that single-strategy
withdrawal function. Governance record 018 is ready but had not executed at the snapshot.
Do not assume that permission is available on the deployed proxy until the upgrade executes.

The v2 migration's v1 drain operations rely on this added ADMIN permission.
They are governance transactions, not user withdrawal entry points.

## Integration boundaries

Controller does not replace AMM, hold the user's queued EVE, or send processed payouts
directly to users. AMM holds escrow and credits claimable ETH; the user claims from AMM.
Controller operations still depend on pause flags, strategy capacity, NAV availability,
and queue eligibility.
